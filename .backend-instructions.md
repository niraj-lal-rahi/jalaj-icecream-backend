## Architecture Principles

### 1. **Separation of Concerns**
- Models: Handle database structure and relationships only
- Controllers: Handle HTTP requests/responses and routing
- Services: Encapsulate business logic (reusable across controllers/APIs)
- Traits: Share common response/functionality without code duplication
- Middleware: Handle cross-cutting concerns (auth, request timing, etc.)

### 2. **DRY (Don't Repeat Yourself)**
- **Rule**: If logic is used in 2+ places, extract to a Service class
- **Example**: Performance calculation logic → `SellerPerformanceService`
- **Single Source of Truth**: All related logic must originate from one place
- **Change Propagation**: One change in service = everywhere updates automatically

### 3. **SOLID Principles**
- **S**ingle Responsibility: One class = one reason to change
- **O**pen/Closed: Open for extension, closed for modification
- **L**iskov Substitution: Substitutable implementations
- **I**nterface Segregation: Specific interfaces, not fat ones
- **D**ependency Inversion: Depend on abstractions, not concretions

## Configuration Management

### **Principle: Constants Segregation**
All hardcoded values, thresholds, percentages, and magic numbers MUST be stored in configuration files, not scattered throughout code.

**Why:**
- Single source of truth for all constants
- Easy to change values (business requirement changes)
- Zero duplication (change once, applies everywhere)
- Config values can be environment-specific
- Testable (inject config into services)

## Repository Pattern

### **Principle: Separate Database Queries from Business Logic**
All database queries should be isolated in Repository classes. Services and Controllers should never execute raw queries.

**Why:**
- Models stay clean (only relationships & structure)
- Queries are testable in isolation
- Easy to optimize queries (one place to change)
- Ability to swap implementations (DB → Cache → API)
- Clear responsibility boundary: QueryRepository vs BusinessLogicService

### **Repository Structure**

```
app/
├── Repositories/           # NEW: Database access layer
│   ├── Contracts/          # Interfaces
│   │   ├── SaleRepository.php (interface)
│   │   ├── SellerRepository.php (interface)
│   │   └── ItemRepository.php (interface)
│   └── Eloquent/
│       ├── SaleRepository.php (implementation)
│       ├── SellerRepository.php (implementation)
│       └── ItemRepository.php (implementation)
├── Services/               # Business logic (uses repositories)
│   ├── SellerPerformanceService.php (uses SellerRepository + SaleRepository)
│   ├── DashboardStatisticsService.php (uses all repositories)
│   └── SalesReportExporter.php (uses SaleRepository)
└── Models/                 # Data structure only
    ├── Sale.php
    ├── Seller.php
    └── Item.php
```

### **Repository Interface Definition**

```php

// app/Repositories/Contracts/SaleRepository.php

namespace App\Repositories\Contracts;

use Illuminate\Database\Eloquent\Collection;

interface SaleRepository
{
    /**
     * Fetch sales by date range with eager-loaded relationships
     * 
     * @param \DateTime $from
     * @param \DateTime $to
     * @return Collection
     */
    public function getSalesByDateRange(\DateTime $from, \DateTime $to): Collection;

    /**
     * Fetch sales for a specific seller on a date
     */
    public function getSalesBySellerOnDate(int $sellerId, \DateTime $date): Collection;

    /**
     * Get top performing sales (by amount)
     */
    public function getTopSalesByAmount(int $limit = 10): Collection;

    /**
     * Count total sales in date range
     */
    public function countSalesByDateRange(\DateTime $from, \DateTime $to): int;

    /**
     * Calculate total amount by date range
     */
    public function getTotalAmountByDateRange(\DateTime $from, \DateTime $to): float;
}
```

### **Repository Implementation**

```php
<?php
// app/Repositories/Eloquent/SaleRepository.php

namespace App\Repositories\Eloquent;

use App\Models\Sale;
use App\Repositories\Contracts\SaleRepository as SaleRepositoryContract;
use Illuminate\Database\Eloquent\Collection;

class SaleRepository implements SaleRepositoryContract
{
    /**
     * Get all database queries with proper eager loading
     * Returns only Collection (no query, already executed)
     */
    public function getSalesByDateRange(\DateTime $from, \DateTime $to): Collection
    {
        return Sale::whereBetween('date', [$from, $to])
            ->with('item', 'seller')  // ✅ Eager load to prevent N+1
            ->get();
    }

    public function getSalesBySellerOnDate(int $sellerId, \DateTime $date): Collection
    {
        return Sale::where('seller_id', $sellerId)
            ->whereDate('date', $date)
            ->with('item')
            ->get();
    }

    public function getTopSalesByAmount(int $limit = 10): Collection
    {
        return Sale::orderByDesc('total')
            ->with('item', 'seller')
            ->limit($limit)
            ->get();
    }

    // ... other methods
}
```

### **Service Using Repository**

```php
<?php
// app/Services/DashboardStatisticsService.php

namespace App\Services;

use App\Repositories\Contracts\SaleRepository;
use App\Repositories\Contracts\SellerRepository;

class DashboardStatisticsService
{
    public function __construct(
        private SaleRepository $saleRepository,
        private SellerRepository $sellerRepository,
    ) {}

    /**
     * Business logic: Calculate dashboard metrics
     * Uses repositories for ALL database access
     */
    public function getTodayStatistics(): array
    {
        $today = now()->startOfDay();
        $tomorrow = now()->addDay()->startOfDay();

        // ✅ Get data from repository
        $todaySales = $this->saleRepository->getSalesByDateRange($today, $tomorrow);

        // ✅ Business logic (not database logic)
        return [
            'total_volume' => $todaySales->count(),
            'total_value' => $todaySales->sum('total'),
            'average_sale' => $todaySales->avg('total'),
            'top_sellers' => $this->calculateTopSellers($todaySales),
        ];
    }

    private function calculateTopSellers($sales)
    {
        return $sales->groupBy('seller_id')
            ->map(fn($group) => [
                'seller_id' => $group[0]->seller_id,
                'count' => $group->count(),
                'total' => $group->sum('total'),
            ])
            ->sortByDesc('total')
            ->values();
    }
}
```

## Service Layer Pattern

### When to Create a Service
✅ **Create a Service when:**
- Logic is used in 2+ places (controllers, APIs, scheduled jobs)
- Business logic is complex (calculations, workflows, transformations)
- Logic needs to be reusable and testable in isolation
- Changes to logic should propagate everywhere automatically

❌ **Don't create a Service when:**
- It's a simple one-time operation
- It's a CRUD operation (use Model + FormRequest instead)
- It's just wrapping a single Eloquent query

### Service Class Template
```php
<?php

namespace App\Services;

use App\Models\User;
use Illuminate\Support\Collection;

class ExampleService
{
    /**
     * Public method - primary business logic
     * 
     * @param int $id
     * @return Collection
     */
    public function getProcessedData(int $id): Collection
    {
        $rawData = $this->fetchData($id);
        return $this->transformData($rawData);
    }

    /**
     * Private method - helper (not exposed publicly)
     */
    private function fetchData(int $id): Collection
    {
        return User::find($id)->getData();
    }

    /**
     * Private method - internal transformation
     */
    private function transformData(Collection $data): Collection
    {
        return $data->map(fn($item) => [
            'id' => $item->id,
            'processed' => $item->value * 2,
        ]);
    }
}
```

### Controller Usage
```php
<?php

namespace App\Http\Controllers\API;

use App\Services\ExampleService;

class ExampleController extends Controller
{
    public function index()
    {
        // ✅ CORRECT: Use service for reusable business logic
        $service = new ExampleService();
        $data = $service->getProcessedData(1);

        return $this->success($data, 'Data retrieved successfully');
    }
}
```

### Model Guidelines

### Query Optimization
```php
// ❌ N+1 Problem
$sellers = Seller::all();
foreach ($sellers as $seller) {
    $count = $seller->sales()->count();  // Query in loop!
}

// ✅ Eager load
$sellers = Seller::with('sales')->get();
foreach ($sellers as $seller) {
    $count = $seller->sales()->count();  // No query
}

// ✅ Even better: Use relation count
$sellers = Seller::withCount('sales')->get();
echo $seller->sales_count;  // No query
```

### Query Scopes (Reusable Query Builders)

**Principle:** Common query filters should be encapsulated in model scopes, not scattered in repositories or controllers.

**Benefits:**
- Reusable across repositories, services, and controllers
- Single place to modify query logic
- Chainable and composable
- Improves readability and maintainability

```php
<?php
// app/Models/Sale.php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Builder;

class Sale extends Model
{
    /**
     * Scope: Filter by date range
     * Usage: Sale::dateRange($from, $to)->get()
     */
    public function scopeDateRange(Builder $query, $from, $to): Builder
    {
        return $query->whereBetween('date', [$from, $to]);
    }

    /**
     * Scope: Filter by seller
     * Usage: Sale::bySeller($id)->get()
     */
    public function scopeBySeller(Builder $query, int $sellerId): Builder
    {
        return $query->where('seller_id', $sellerId);
    }

    /**
     * Scope: Filter by specific date
     * Usage: Sale::forDate(now())->get()
     */
    public function scopeForDate(Builder $query, $date): Builder
    {
        return $query->whereDate('date', $date);
    }

    /**
     * Scope: Eager load common relationships
     * Usage: Sale::withRelations()->get()
     */
    public function scopeWithRelations(Builder $query): Builder
    {
        return $query->with('item', 'seller');
    }

    /**
     * Scope: Order by recent first
     * Usage: Sale::latest()->get()
     */
    public function scopeLatest(Builder $query): Builder
    {
        return $query->orderByDesc('created_at');
    }

    /**
     * Scope: Chaining multiple scopes
     * Usage: Sale::forDate(now())->bySeller(1)->withRelations()->latest()->get()
     */
}
```

**Using Scopes in Repository:**

```php
<?php
// app/Repositories/Eloquent/SaleRepository.php

public function getSalesByDateRange($from, $to): Collection
{
    // ✅ CORRECT: Uses model scope
    return Sale::dateRange($from, $to)->withRelations()->get();
}

{
    // ✅ CORRECT: Chains scopes
    return Sale::forDate($date)
        ->bySeller($sellerId)
        ->withRelations()
        ->get();
}
```

## Error Handling & Logging

### Exception Handling Pattern
```php
try {
    // Business logic
    $result = $service->process($data);
    
} catch (ValidationException $e) {
    // Expected validation errors → 422
    Log::warning('Validation failed', ['errors' => $e->errors()]);
    return $this->error('Validation failed', 422, $e->errors());
    
} catch (NotFoundException $e) {
    // Resource not found → 404
    Log::notice('Resource not found', ['resource' => $e->resource]);
    return $this->error('Resource not found', 404, $e->getMessage());
    
} catch (UnauthorizedException $e) {
    // User not authorized → 403
    Log::warning('Unauthorized access', ['user' => auth()->id()]);
    return $this->error('Unauthorized', 403, $e->getMessage());
    
} catch (Exception $e) {
    // Unexpected errors → 500
    Log::error('Unexpected error', [
        'message' => $e->getMessage(),
        'file' => $e->getFile(),
        'line' => $e->getLine(),
        'trace' => $e->getTraceAsString(),
    ]);
    return $this->error('Server error', 500, $e->getMessage());
}
```


### 2. **Input Validation**
```php
// ✅ Always validate user input
public function store(CreateSaleRequest $request)
{
    // Validation happens in FormRequest (not controller)
    $data = $request->validated();
    // ... process validated data
}

// FormRequest class
class CreateSaleRequest extends FormRequest
{
    public function rules(): array
    {
        return [
            'seller_id' => 'required|exists:sellers,id',
            'item_id' => 'required|exists:items,id',
            'quantity' => 'required|integer|min:1',
            'price' => 'required|numeric|min:0',
        ];
    }
}
```

### 3. **SQL Injection Prevention**
```php
// ❌ NEVER use string interpolation
$sales = DB::select("SELECT * FROM sales WHERE seller_id = $id");

// ✅ Use parameterized queries
$sales = DB::select('SELECT * FROM sales WHERE seller_id = ?', [$id]);
// or
$sales = Sale::where('seller_id', $id)->get();
```

### 4. **Mass Assignment Protection**
```php
// Model class
protected $fillable = ['name', 'email', 'phone'];
// Only these can be mass-assigned; others ignored

// ❌ Bad
$seller = Seller::create($request->all());  // May expose is_admin, etc.

// ✅ Good
$seller = Seller::create($request->validated());  // Only validated fields
```

### 5. **CORS & API Security**
```php
// config/cors.php
'allowed_origins' => ['https://mobile-app.com', 'https://admin.domain.com'],
'allowed_methods' => ['GET', 'POST', 'PUT', 'DELETE'],
'allowed_headers' => ['Content-Type', 'Authorization'],
```

## Key Reminders

1. **Single Source of Truth**: Business logic should exist in ONE place (Service class)
2. **Reusability First**: If code is used 2+ times, make it a Service
3. **Separation of Concerns**: Models ≠ Logic, Controllers ≠ Logic, Repositories = Queries, Services = Logic
4. **Configuration Management**: ALL hardcoded values go in `config/` files (profit.php, performance.php, cache.php, pagination.php)
5. **Repository Pattern**: Database queries live in Repositories, Services use Repositories (not Model::all())
6. **Query Scopes**: Reusable filters as model scopes, not scattered in repositories
7. **Type Hints**: Always specify parameter & return types
8. **Documentation**: Explain the "why", not just the "what"
9. **Error Handling**: Handle expected vs unexpected errors differently
10. **Logging**: Log for debugging, meaningful context + relevant keys
11. **Performance**: Eager load relationships, use scopes, prevent N+1 queries
12. **Security**: Never trust user input, use FormRequest validation centrally
13. **Testing**: Test behavior, not implementation - use RefreshDatabase + AAA pattern
14. **Eager Loading**: Always include `->with('relation')` in repository queries
